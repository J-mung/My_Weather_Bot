### 배경

현재 애플리케이션은 메인, 검색, 북마크 화면 각각의 기능은 확장되어 왔지만,
웹뷰와 모바일뷰를 함께 고려한 레이아웃 기준은 아직 충분히 정리되지 않은 상태다.

그 결과 다음과 같은 위험이 있다.

- 화면 폭이 달라질 때 카드 비율과 여백이 불안정해진다.
- 긴 지역명, 버튼, 아이콘이 특정 breakpoint에서 어색하게 겹치거나 줄바꿈된다.
- 한 화면에서 수정한 스타일이 다른 화면 또는 다른 뷰포트에 영향을 줄 수 있다.
- 모바일 대응을 위해 추가한 스타일이 웹뷰 밀도를 깨뜨리거나, 반대로 웹 기준 스타일이 모바일에서 답답하게 보일 수 있다.

이번 작업의 목적은 화면을 새로 디자인하는 것이 아니라,
웹뷰와 모바일뷰 모두에서 **안정적으로 동작하는 레이아웃 기준을 문서화하고 순차적으로 적용하는 것**이다.

### 목표

1. 웹뷰와 모바일뷰를 하나의 코드베이스에서 함께 안정적으로 지원한다.
2. 고정 폭/높이 의존을 줄이고, 반응형 레이아웃 기준을 명확히 한다.
3. 공통 레이아웃 원칙을 먼저 정하고, 페이지별 적용 순서를 통제한다.
4. 기능 변경 없이도 화면 구조가 덜 깨지는 상태를 만든다.

### 범위

이번 안정성 작업은 다음 범위를 포함한다.

1. 전역 레이아웃
- 앱 최대 폭
- 기본 여백
- 섹션 간격
- 헤더 / 푸터 / 콘텐츠 영역 관계

2. 메인 화면
- 현재 날씨 카드
- 시간대별 예보 strip
- 섹션 간 간격 및 정보 배치

3. 검색 화면
- 검색 입력 영역
- 검색 결과 리스트
- 하이라이트 텍스트와 액션 버튼 배치

4. 북마크 화면
- 카드 grid
- 카드 내부 텍스트/버튼/메뉴 정렬

### 기본 원칙

#### 1. 모바일 우선, 웹 확장

모바일과 웹을 각각 따로 구현하는 방식이 아니라,
모바일을 기본 구조로 두고 breakpoint를 통해 웹으로 확장하는 방식을 채택한다.

의사코드:

```txt
기본 스타일
-> 모바일 기준 단일 컬럼, 촘촘한 여백

md / lg 이상
-> 가로 배치 확장
-> grid 열 수 증가
-> 텍스트/아이콘 밀도 조정
```

#### 2. 절대 크기 최소화

다음 속성은 레이아웃 기준으로 남용하지 않는다.

- `w-[...]`
- `h-[...]`
- `min-w-[...]`
- `min-h-[...]`

우선적으로 사용할 것:

- `w-full`
- `max-w-*`
- `grid-cols-*`
- `flex-col`, `md:flex-row`
- `overflow-x-auto`
- `min-w-0`

#### 3. 레이아웃과 표현 책임 분리

컴포넌트 내부에서 “데이터 표시”와 “레이아웃 제어”가 섞이지 않도록 한다.

예:

- 현재 날씨 데이터 계산은 model / mapper 계층
- 카드 폭/정렬/spacing은 `styles.ts`
- 화면 구조는 `page` 또는 `layout` 계층

#### 4. 공통 규칙 먼저, 페이지별 최적화는 나중

개별 카드부터 손대지 않고,
먼저 전역 레이아웃 규칙과 페이지 공통 spacing 기준을 정한 뒤
세부 컴포넌트를 다듬는다.

### 전역 레이아웃 기준

우선 확정해야 할 항목은 다음과 같다.

1. 앱 최대 폭
- 웹에서 콘텐츠가 지나치게 넓어지지 않도록 상한 설정

2. 기본 좌우 패딩
- 모바일 / 태블릿 / 웹의 padding 단계 정의

3. 섹션 간 vertical rhythm
- `space-y-*` 또는 `gap-*`의 공통 기준 정리

4. 헤더 / 본문 / 푸터 관계
- 푸터가 콘텐츠를 밀지 않는지
- 모바일 하단 여백이 충분한지

### 페이지별 적용 우선순위

#### 1. 메인 화면

가장 먼저 안정화해야 할 화면이다.

이유:

- 현재 날씨 카드
- 시간대별 예보
- 검색 진입점
- 북마크 진입 흐름

등 핵심 기능이 모두 한 화면에 모여 있기 때문이다.

우선 확인할 요소:

- `NowInfoCard`의 제목/온도/아이콘 배치
- `HourlyInfoCard`의 가로 스크롤과 카드 폭
- 섹션 간 간격
- 긴 지역명과 버튼 정렬

#### 2. 검색 화면

검색 기능이 강화된 만큼,
레이아웃은 단순하고 안정적이어야 한다.

우선 확인할 요소:

- 검색 입력창 폭
- 결과 카드 padding
- 긴 지역명 줄바꿈
- 하이라이트 텍스트와 북마크 버튼의 간섭 여부

#### 3. 북마크 화면

북마크는 grid 기반 레이아웃이므로,
모바일과 웹에서 열 수 변화에 따른 안정성이 중요하다.

우선 확인할 요소:

- `1 / 2 / 3열` 전환 기준
- 카드 내부 텍스트 overflow
- 컨텍스트 메뉴 버튼 정렬
- 편집 모드에서도 높이와 정렬이 유지되는지

### 적용 순서

의사코드:

```txt
1. MainLayout 기준 폭 / padding / spacing 정리
2. 메인 화면 카드 레이아웃 안정화
3. 시간대별 예보 strip 안정화
4. 검색 결과 카드 정렬 안정화
5. 북마크 grid 및 카드 내부 정렬 안정화
6. 마지막에 header / footer 재점검
```

### 검증 기준

안정성 작업은 다음 3개 폭에서 반복적으로 확인해야 한다.

1. 모바일
- 약 375px

2. 태블릿
- 약 768px

3. 웹
- 약 1280px 이상

각 뷰포트에서 확인할 항목:

- overflow 발생 여부
- 카드 비율 붕괴 여부
- 긴 지역명 줄바꿈
- 버튼과 텍스트 정렬
- 가로 스크롤 strip 동작
- 하단 여백 부족 여부

### 체크리스트

#### 공통

- 레이아웃 기준이 `w-full`, `max-w-*` 중심인지
- 불필요한 절대 크기 값이 없는지
- breakpoint가 `mobile -> tablet -> web` 순서로 읽히는지

#### 메인 화면

- 현재 날씨 카드의 제목/버튼/아이콘이 안정적으로 정렬되는지
- 시간대별 예보 strip이 모바일/웹 모두에서 읽기 쉬운지
- 새로고침 상태 표시가 레이아웃을 흔들지 않는지

#### 검색 화면

- 자동 검색 결과가 화면을 과도하게 밀지 않는지
- 하이라이트 텍스트와 액션 버튼이 충돌하지 않는지
- 결과 카드가 모바일에서도 충분히 탭하기 쉬운지

#### 북마크 화면

- grid 전환 시 카드 폭이 불안정하지 않은지
- 지역명, 별칭, 좌표 텍스트가 깨지지 않는지
- 편집 폼과 카드 뷰 사이의 레이아웃 차이가 과도하지 않은지

### 비목표

이번 작업의 비목표는 다음과 같다.

- 전체 UI 리디자인
- 컬러 시스템 변경
- 타이포그래피 전면 교체
- 애니메이션 중심 개선

즉, 이번 문서와 작업의 목적은 “멋지게 바꾸는 것”이 아니라
“웹과 모바일 모두에서 덜 깨지고 안정적으로 보이게 만드는 것”이다.

### 한 줄 요약

웹뷰/모바일뷰 안정성 작업은 개별 컴포넌트를 즉흥적으로 손보는 방식이 아니라,
전역 레이아웃 기준을 먼저 고정한 뒤 `메인 -> 검색 -> 북마크` 순서로 breakpoint 안정성을 점검하고 적용하는 방식으로 진행한다.
