### 배경

현재 레이아웃은 웹뷰 기준 헤더 구조를 모바일에서도 그대로 사용하고 있다.

현재 헤더는 다음 요소를 한 줄에 배치한다.

- 브랜드 로고 및 앱 이름
- 상단 네비게이션 버튼 (`Main`, `Search`, `bookmark`)

이 구조는 웹뷰에서는 자연스럽지만, 폭이 좁은 모바일 기기에서는 다음 문제가 발생한다.

- 헤더 내부 요소의 총 너비가 뷰포트보다 넓어질 수 있다.
- 그 결과 문서 전체에 가로 overflow가 발생한다.
- 사용자는 우측에 불필요한 여백이 생기거나 x 스크롤이 가능한 상태를 보게 된다.
- 특히 `iPhone SE`나 접힌 상태의 `Galaxy Z Fold 5`처럼 폭이 좁은 기기에서 문제가 더 쉽게 드러난다.

즉, 현재 문제의 직접 원인은 "모바일 폭에서 상단 헤더가 감당해야 하는 정보량이 너무 많다"는 점이다.

### 문제 정의

현재 구조의 인과관계를 정리하면 다음과 같다.

```txt
웹 기준 헤더 구조를 모바일에 그대로 유지
-> 브랜드와 nav 버튼이 한 줄에 함께 배치됨
-> 좁은 화면에서 내부 요소 총합 폭이 뷰포트를 초과함
-> 페이지 전체에 가로 overflow 발생
-> 우측 여백처럼 보이는 빈 공간 또는 x 스크롤 발생
```

여기서 핵심은, 전체 레이아웃에 `w-full`을 주는 것만으로는 해결되지 않는다는 점이다.

이유는 다음과 같다.

- `w-full`은 부모 폭을 맞출 뿐이다.
- 실제 overflow는 내부 자식 요소의 최소 필요 폭 때문에 발생한다.
- 따라서 문제 해결 지점은 전체 wrapper가 아니라, 모바일에서의 헤더 정보 구조 자체다.

### 변경 목표

이번 변경의 목표는 단순히 x 스크롤을 막는 것이 아니다.

다음 세 가지를 함께 달성해야 한다.

1. 모바일에서 헤더 폭 초과 문제를 제거한다.
2. 상단 네비게이션 부담을 줄이고 모바일에 맞는 탐색 구조로 바꾼다.
3. 스크롤 방향에 따라 푸터 네비게이션의 노출 상태를 제어해 가시성과 화면 활용도를 함께 확보한다.

### 변경 방향

#### 1. 모바일에서는 헤더에서 nav를 제거한다.

원인:
- 헤더 가로 폭 초과의 핵심 원인이 브랜드 + nav 동시 노출에 있다.

변경:
- 웹뷰에서는 현재 헤더 구조를 유지한다.
- 모바일뷰에서는 헤더에 브랜드만 남기고 nav 버튼은 제거한다.

효과:
- 헤더 내부 총 너비가 줄어든다.
- 모바일 좁은 화면에서 가로 overflow 가능성이 크게 줄어든다.
- 상단 구조가 단순해져 현재 화면 정보에 더 집중할 수 있다.

의사코드:

```txt
if viewport >= md
  -> 현재 헤더 유지
else
  -> 브랜드만 노출
  -> nav는 숨김
```

#### 2. 모바일에서는 nav를 footer로 이동한다.

원인:
- 모바일에서는 상단보다 하단 탐색이 엄지 사용성과 시선 이동 측면에서 더 유리하다.
- 현재 상단 헤더에 nav를 두면 좁은 화면에서 정보 밀도가 과해진다.

변경:
- 모바일 전용 bottom navigation을 footer 영역에 둔다.
- 출력 항목은 `bookmark`, `search` 두 개로 제한한다.
- `bookmark`는 좌측, `search`는 우측에 배치한다.

효과:
- 상단 혼잡도가 줄어든다.
- 모바일 탐색 접근성이 좋아진다.
- 사용자가 자주 쓰는 보조 기능을 하단에서 빠르게 접근할 수 있다.

의사코드:

```txt
if viewport < md
  -> footer에 mobile nav 노출
  -> left: bookmark
  -> right: search
else
  -> 기존 footer 노출
```

#### 3. 모바일 footer nav는 일반 footer가 아니라 fixed bottom navigation으로 구현한다.

원인:
- `sticky bottom-0`는 부모 레이아웃과 스크롤 컨텍스트 영향을 많이 받는다.
- 모바일 하단 탐색은 문서 흐름보다 화면 기준 고정이 더 적합하다.

변경:
- 모바일 nav는 `fixed bottom-0` 기준으로 구현한다.
- 본문은 하단 nav 높이만큼 별도 padding을 확보한다.

효과:
- 기기별로 더 안정적인 위치 고정이 가능하다.
- 마지막 콘텐츠가 nav 아래에 가려지는 문제를 방지할 수 있다.

의사코드:

```txt
mobile footer nav
-> fixed bottom-0 inset-x-0
main content
-> mobile bottom padding 추가
```

#### 4. 스크롤 방향에 따라 footer nav를 숨김/노출한다.

원인:
- 모바일에서 하단 nav를 항상 고정하면, 화면 높이가 작은 기기에서는 콘텐츠 영역을 계속 차지한다.
- 반대로 완전히 없애면 탐색 접근성이 떨어진다.

변경:
- 아래로 스크롤할 때는 footer nav를 숨긴다.
- 위로 스크롤할 때는 footer nav를 다시 노출한다.
- 상단 근처에서는 항상 노출한다.

효과:
- 콘텐츠를 읽을 때는 더 많은 세로 공간을 확보할 수 있다.
- 다시 탐색하고 싶을 때는 위로 스크롤만으로 nav를 되찾을 수 있다.

의사코드:

```txt
scroll event 발생
-> 현재 scrollY와 이전 scrollY 비교
-> 아래로 스크롤: nav hidden
-> 위로 스크롤: nav visible
-> top 근처: nav visible 유지
```

#### 5. 상태 전환은 transform 애니메이션으로 처리한다.

원인:
- 모바일 네비게이션이 갑자기 사라지거나 나타나면 시각적으로 거칠다.
- opacity만으로는 하단 패널의 이동감을 충분히 설명하기 어렵다.

변경:
- `translateY` 기반으로 노출 상태를 전환한다.
- `visible -> translate-y-0`
- `hidden -> translate-y-full`
- transition duration과 easing을 같이 적용한다.

효과:
- 상태 변화가 자연스럽게 보인다.
- 사용자가 숨김/노출 규칙을 더 쉽게 학습할 수 있다.

의사코드:

```txt
if visible
  -> translate-y-0
else
  -> translate-y-full

항상 transition-transform 적용
```

### 기대 효과

이번 변경이 적용되면 다음 결과를 기대할 수 있다.

1. 모바일 헤더 폭 초과 문제 완화
- 브랜드만 남는 구조로 상단 가로 폭이 줄어든다.
- 좁은 화면에서 x 스크롤 발생 가능성이 낮아진다.

2. 모바일 탐색 구조 개선
- 검색과 북마크를 하단에 배치해 엄지 접근성이 좋아진다.
- 상단은 현재 화면 정보 중심, 하단은 탐색 중심으로 역할이 분리된다.

3. 콘텐츠 가시 영역 확대
- 아래로 스크롤할 때 하단 nav가 숨겨져, 작은 기기에서도 본문 활용 면적이 커진다.

4. 화면 상태 변화의 자연스러운 전달
- transform 애니메이션으로 하단 nav 상태 변화가 덜 거칠게 보인다.
- 인터랙션 규칙을 사용자가 빠르게 이해할 수 있다.

### 구현 범위

이번 작업의 직접 수정 대상은 다음과 같다.

1. Header
- 모바일에서 nav 제거
- 웹에서는 현재 구조 유지

2. Footer
- 웹용 footer 유지
- 모바일 전용 bottom navigation 추가
- scroll direction 기반 노출 상태 제어 추가

3. MainLayout
- 모바일 하단 nav 높이를 고려한 콘텐츠 padding 추가
- 불필요한 최소 폭 강제 속성 재검토

### 검증 기준

변경 후 다음 항목을 확인한다.

1. `iPhone SE` 폭에서 x 스크롤이 사라지는지
2. `Galaxy Z Fold 5` 접힌 폭에서 우측 여백처럼 보이던 overflow가 줄어드는지
3. 웹뷰에서 기존 헤더 레이아웃이 유지되는지
4. 모바일에서 `bookmark`, `search`가 footer 좌/우에 올바르게 배치되는지
5. 아래로 스크롤 시 footer nav가 자연스럽게 숨는지
6. 위로 스크롤 시 footer nav가 자연스럽게 다시 나타나는지
7. 마지막 콘텐츠가 footer nav 아래에 가려지지 않는지
